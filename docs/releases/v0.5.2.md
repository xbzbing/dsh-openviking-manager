## 主要变更

- **工作区现状卡片重做**：每个工作区改为两行——第一行是路径和状态标签（共享 / 已隔离 / 用户级空间，悬停显示共享对象或隔离说明），第二行固定显示 peer；列表上方新增按路径的本地搜索与状态筛选（宿主官方下拉菜单，默认「全部状态」），工作区多时可以直接筛。
- **工作区层的规则进入面板**：项目记忆卡片与工作区列表读取仓库（`.openviking/config.json`、`config.local.json`、`~/.openviking/workspaces/<slot>.json`）声明的 `peer.source`、`peer.id` 与召回键并只读展示，标出哪些目录落到同一个 peer；宿主无法枚举工作区时整段隐藏，超过检查上限时标明列表不完整。
- **管理接口安全加固**：只接受本服务实际响应的 Host（回环地址与绑定源，反向代理可用 `DSH_OPENVIKING_MANAGER_ALLOWED_HOSTS` 追加），拒绝跨站 `Sec-Fetch-Site` 与 Origin 不匹配；更换端点源时清空已存 `user_key` 而不转发给新地址；短 key 全掩码。
- **修复与内部**：版本比较支持 semver 预发布排序（`rc.2` < `rc.10`）；版本查询、连接探测与 Admin API 分别加 8–15 秒超时；Admin 返回非 JSON 错误时不再被解析异常掩盖；召回调优保存只提交改动字段，环境变量或工作区覆盖的键不会被文件值回写；管理表单拆成 5 张卡片。`npm run check` 覆盖两行布局、tag 提示、搜索与筛选组合。

## English

- **Workspace status card rebuilt**: each workspace now uses two lines — the first holds the path and a status tag (Shared / Isolated / User-level space; hover for the shared peers or the isolation reason), and the peer always sits on the second line. The list gained a local path search and a status filter (the shell's own dropdown menu, "All statuses" by default), so a long registry can be narrowed in place.
- **Workspace-layer rules surface in the panel**: the project-memory card and the workspace list read the declarations a repository makes in `.openviking/config.json`, `config.local.json` and `~/.openviking/workspaces/<slot>.json` for `peer.source`, `peer.id` and the recall knobs, show them read-only, and mark which directories land on the same peer. A host that cannot enumerate workspaces hides the list; a registry over the inspection cap says the list is partial.
- **Manager API hardening**: routes accept only a Host this server actually answers for (loopback and the bound origin; reverse proxies can add one through `DSH_OPENVIKING_MANAGER_ALLOWED_HOSTS`) and refuse cross-site `Sec-Fetch-Site` or a mismatched Origin. Changing the endpoint origin clears the stored `user_key` instead of forwarding it, and short keys are masked completely.
- **Fixes and internals**: semver prerelease ordering (`rc.2` < `rc.10`); 8–15s timeouts on the version check, the probe and the Admin API; Admin error bodies are read before the status, so a non-JSON response no longer hides it; recall tuning submits only changed fields, so env- or workspace-overridden keys are never written back; the manager form is split into five cards. `npm run check` covers the two-line rows, tag tooltips, and the search/filter combination.
