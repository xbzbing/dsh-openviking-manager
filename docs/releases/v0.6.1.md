## 主要变更

- **移除「项目目录」解析面板**：隔离卡片里那个可填路径、显示「仓库根 / 项目 peer / 召回范围」的区块已整块删除。它只是只读预览，却长得像一个已保存的项目路径——宿主在 `~/.dsh` 这类目录里启动时，页面上写着 `项目目录 /Users/ankh/.dsh`、`项目 peer -Users-ankh--dsh`，很容易被理解成插件把项目配置到了那里。现在隔离卡片只留召回范围的开关与说明。
- **工作区状态接手诊断信息**：侧栏每个 workspace 的条目仍显示路径、peer 与共享关系，并新增该目录生效的隔离风险（跨项目召回、召回/捕获被关、peer 被钉死、推导不出 peer 等），同时列出它自己声明的覆盖键；风险文案带上具体的层与 peer 值，不再只给一个代码。
- **服务端版本标签写清归属**：验证连接成功后的版本胶囊从 `OpenViking v0.5.5` 改为 `服务端 OpenViking 版本：v0.5.5`（英文 `Server OpenViking version: v0.5.5`），不再需要猜这是插件版本还是服务端版本。
- **内部**：删掉仅该面板使用的 14 个 i18n 键、`?cwd=` 传参路径与对应样式；`/workspaces` 返回的 `risks` 从代码字符串改为带插值的对象。

## English

- **The project directory panel is gone**: the block in the isolation card that took a path and showed "repository root / project peer / recall scope" has been removed entirely. It was a read-only preview, but it looked like a saved project path — with the host started in a directory such as `~/.dsh`, the page read `Project directory /Users/ankh/.dsh` and `Project peer -Users-ankh--dsh`, which is easy to mistake for this plugin having configured the project there. The card now carries only the recall-scope switch and its explanation.
- **Workspace status takes over the diagnostics**: each sidebar workspace row still shows its path, peer and shared namespaces, and now also reports the isolation risks in effect for that directory (cross-project recall, recall or capture turned off, a pinned peer, no derivable peer, and so on) plus the workspace keys it declares itself. The copy interpolates the actual layer and peer values instead of showing a bare code.
- **The server version badge names its owner**: after a successful verify, the badge reads `Server OpenViking version: v0.5.5` instead of `OpenViking v0.5.5`, so it no longer takes a guess whether that is the plugin or the server.
- **Internal**: dropped the 14 i18n keys, the `?cwd=` parameter path and the styles used only by that panel; `/workspaces` now returns `risks` as objects with the values the UI interpolates instead of bare codes.
