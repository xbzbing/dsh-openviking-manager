## 主要变更

- **事件衰减保护的默认值跟上官方的 `30d`**：官方插件 0.5.41 起把 dsh 的 `recallEventsDecayProtection` 默认值从空（不保护）改为 `30d`。配置页此前仍按旧默认提示「留空＝不保护」，恰好与升级后的实际行为相反；现在字段留空即恢复官方默认，提示标明 `30d` 与 `off` 都需要 0.5.41+，旧版请留空。
- **`off` 现在可以直接保存**：调优卡片此前只接受时长，官方支持的 `off`（关闭衰减保护）会被校验拒绝，想关只能手改 `ovcli.conf`。现在接受服务端时长或 `off`，大小写自动归一为 `off`；非法值仍然拒绝且不落盘。
- **兼容性声明更新到 0.5.44**：README 的官方插件测试基线从 0.5.34 改为 0.5.44，并补充 0.5.41–0.5.44 的行为变化：事件衰减默认值、`ov-memory-doctor`、0.5.42 的会话历史指针，以及 0.5.44 只有 schema 声明、尚未接线的 `sealSecrets` / `enrollToolSecrets`。

## English

- **Event decay protection now follows the official `30d` default**: since official plugin 0.5.41 the dsh default for `recallEventsDecayProtection` changed from empty (no protection) to `30d`. The configuration page still said "empty = no protection", the opposite of the post-upgrade behavior; empty now restores the official default, and the hint states that both 30d and off require 0.5.41+, so older versions should leave the field empty.
- **`off` can now be saved directly**: the tuning card only accepted durations, so the official `off` value (disable decay protection) was rejected and the only way to turn protection off was editing `ovcli.conf` by hand. It now accepts a server duration or `off`, normalizing the case to `off`; invalid values are still rejected without touching the file.
- **Compatibility notes updated to 0.5.44**: the README's official-plugin test baseline moves from 0.5.34 to 0.5.44 and records the 0.5.41–0.5.44 behavior changes: the decay default, `ov-memory-doctor`, the 0.5.42 session-history pointer, and the `sealSecrets` / `enrollToolSecrets` keys that 0.5.44 declares in its schema without a consumer.
