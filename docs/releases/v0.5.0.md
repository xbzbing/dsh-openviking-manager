## 主要变更

- **按项目隔离记忆**：隔离单元从「主题」改成「项目」。同一个项目的多个 agent、多台机器、多个 clone 共用一份记忆；不同项目即使在同一台机器、同一个 agent 上也互相隔离。peer 由官方记忆插件按会话所在工作区的 git 身份推导，不需要再手工维护主题名。
- **记忆隔离规则**：新增一张卡，决定「哪些目录算同一个项目」。默认「仓库优先，其次目录」——同一仓库的 clone 共享，不在 git 里的目录各自独立。这是规则而不是当前会话的设置，每个对话都自动遵循；首次打开配置页就会写入，不必先去配一次。
- **工作区现状**：列出宿主侧边栏里每个工作区解析出的 peer、它与哪些工作区共享记忆、以及该目录自己声明的覆盖项，默认收起。宿主没有工作区注册表时整张卡隐藏，而不是给一个空列表。
- **仓库配置与风险可见**：`.openviking/config.json`、`config.local.json` 和 `~/.openviking/workspaces/<slot>.json` 的优先级高于本插件能写的任何文件。面板现在列出生效的声明、指出是哪一层赢的，并把「放开跨项目召回」「关掉召回或抓取」「仓库钉死 peer」「目录推导不出 peer」「保存的是 root key」逐条列为风险。这些文件仍然只读，本插件不写。
- **召回调优**：暴露官方已声明的 7 个键——分数阈值、条数上限、查询扩写、排除 URI、事件衰减保护、请求超时、召回搜索超时。分数阈值、查询扩写与请求超时在首次打开时按产品默认写入一次（0.5、关闭、15000 毫秒），文件、工作区或环境变量里的取值仍然优先；留空即回到该键的默认值。
- **连接验证与重载不再互相打断**：验证结果直接显示在按钮右侧，长错误信息会换行而不是压掉按钮。首载重载只锁它自己写的那几个控件，重载有 30 秒上限，超时会明说「可能还没生效」；后台重载结束得比你的操作晚时，也不会再盖掉你刚点出来的结果。
- **修复**：工作区列表一直为空——宿主没有 inject 的服务按属性读取会抛错，错误又被吞掉，于是任何宿主都显示「没有注册的工作区」；「已连接为 /user」（服务端只返回用户、不返回账号时的空账号与多余斜杠）；环境变量告警把变量名写死成 `OPENVIKING_RECALL_PEER_SCOPE`；被仓库层或环境变量覆盖的开关仍可编辑、保存后却不生效；工作区文件里的 `min_client_version` 从不告警；官方插件 0.5.29 的重载失效（该版本入口会 import 宿主包）。
- **内部**：`lib/` 不再入库，由 GitHub Actions 在门禁通过后 `npm pack` 出一个 tgz，同一份产物既是 Release 附件也发到 npm，因此 `dsh plugin add github:xbzbing/dsh-openviking-manager` 不再可用（那棵树没有编译产物）。隔离与规则两个选择改用平台自带的 `Menu` / `SegmentedControl`，并按平台约定补齐每个选项对应的 tab 面板。

## English

- **Memory isolation per project**: the isolation unit is now the project rather than a topic. One project shares a single memory across agents, machines and clones, while a different project stays isolated even on the same machine and agent. The peer is derived by the official memory plugin from the session workspace's git identity, so there is no topic name to maintain by hand.
- **A memory isolation rule**: a new card decides which directories count as one project. The default is "repository first, then the directory" — clones of one repository share, directories outside git stay separate. This is a rule, not a per-session setting: every conversation follows it, and it is written on first visit so nothing has to be configured up front.
- **Workspace status**: lists every sidebar workspace with the peer it resolves to, the workspaces it shares memories with, and any override the directory declares; folded by default. A host without a workspace registry hides the whole card instead of showing an empty list.
- **Repository configuration and risks are visible**: `.openviking/config.json`, `config.local.json` and `~/.openviking/workspaces/<slot>.json` outrank anything this plugin can write. The panel now lists the declarations that apply, names the layer that won, and calls out each risk — recall widened across projects, recall or capture switched off, a peer pinned by the repository, a directory that derives no peer, a saved root key. Those files stay read-only; this plugin never writes them.
- **Recall tuning**: the seven official keys are exposed — score threshold, result limit, query expansion, excluded URIs, event decay protection, request timeout and recall search timeout. Score threshold, query expansion and request timeout are written once with the product defaults (0.5, off, 15000 ms); values from a file, a workspace or the environment still win, and clearing a field restores that key's default.
- **Verifying a connection and reloading the plugin no longer collide**: the result renders beside the button that asked, and a long error wraps instead of squeezing the buttons. The first-load reload holds only the controls it writes, has a 30-second budget, and says the setting may not be active yet when it runs out; a background reload that finishes after your action no longer replaces what you just did.
- **Fixes**: the workspace list was always empty — a service read as a plain property throws without `inject` and the error was swallowed, so every host claimed no registered workspaces; "Connected as /user" when the server reports a user but no account (empty account, stray slash); the environment warning hardcoded `OPENVIKING_RECALL_PEER_SCOPE`; controls overridden by a workspace layer or an environment variable stayed editable and silently did nothing when saved; a workspace file's `min_client_version` never warned; reloading the official plugin stopped working with 0.5.29, whose entry imports host packages.
- **Internal**: `lib/` is no longer committed. GitHub Actions runs the gate, then `npm pack` produces one tarball that ships both as the Release asset and to npm, so `dsh plugin add github:xbzbing/dsh-openviking-manager` no longer works (that tree has no build output). The isolation and rule choices now use the platform's own `Menu` / `SegmentedControl`, with the tab panel each option is expected to own.
